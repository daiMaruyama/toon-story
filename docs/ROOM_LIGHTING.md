# 部屋の照明

`ATBRoomLighting` が部屋の範囲・照明状態を管理する。
点灯中と部屋の範囲外では従来どおり。消灯中は、おもちゃと視認した人間のActor中心間の3D距離が
`DA_TBRules` の視界にある「暗い部屋で視線を防ぐ距離」（既定3m）以上の場合、その人間の視線による凍結を防ぐ。
人間側の部屋の状態には依存しない。近距離で見ている人間が1人でもいれば凍結する。
距離の境界は「以上」で統一。0mなら、その部屋で距離による凍結をすべて防ぐ。

`Watched` は視野・遮蔽だけを判定し、`ATBCharacter::CanBeFrozenBy(Observer)` が対象側の保護を判定する。
視認者一覧を保存・複製する必要はなく、サーバーの毎フレームの評価で人間ごとに集約する。
スイッチ操作後も次の評価で凍結・解除が更新される。凍結済みのおもちゃは従来同様E操作できないため、
消灯による救助には別のおもちゃや人間の操作が必要。

## 設定済みのステージ

以下の既存マップには、部屋の範囲・対象ライト・スイッチを保存済み。追加配置なしで試合中にスイッチへ近づき、向き合ってEを押すと切り替えられる。

| マップ | 対象の部屋 | スイッチ |
| --- | --- | --- |
| `TB_KidsRoom` | 西室・東室 | 共有壁沿いに各1個 |
| `TB_ArchViz` | Living・Dining・Library・Study | 中央の仕切り壁沿いに各1個 |
| `TB_ToyWorldDemoExpanded` | Main・Bedroom | 部屋を隔てる壁沿いに各1個 |

World Outlinerの `Gameplay/Lighting` に `RoomLighting_` と `LightSwitch_` をまとめている。
初期状態は全室点灯。スイッチの中心は床上55cm、既存の室内ライトをMovableにして各室へ割り当てた。
人間・おもちゃの両方が床から操作できるように、家具の遮蔽を避けて配置している。
共有の収納別室 `TB_ToyBoxRoom` は今回の対象外。太陽光・SkyLight・発光マテリアルは既存設定のまま。

## 新しい部屋に配置する

1. 各部屋に `TBRoomLighting` を配置し、`RoomBounds` のBox Extentで床から天井までの内部を覆う。
   Actor位置が範囲の中心。回転・スケールに対応する。廊下は範囲外にするか独立した部屋として配置する。
2. `Lights` にその部屋のPoint / Spot / Rect Lightを登録する。1つのライトを複数の部屋に登録しない。
   消灯時は登録ライトのVisibilityをfalse、点灯時はtrueにするので、初期非表示の装飾ライトは登録しない。
3. 対象ライトのMobilityをMovableにする。`Initially Lights On` を設定する。保護距離は `Content/Data/DA_TBRules` で調整する。
4. `TBLightSwitch` を配置して `Room` に対象の部屋を指定する。見た目は既定の白いプレートから
   Meshを変更できる。両チームから到達できる高さ・場所へ置く（例: 床上40cm）。
5. 保存後、人間・おもちゃでスイッチに向き合いEを押す。既定の操作距離は目線からInteractionPointまで180cm、壁越しは操作できない。
   距離は `Content/Data/DA_LightSwitch` の「操作できる距離」で調整する。
   配置ごとに別の調整値を使う場合は同じ型のDAを作り、`Switch Data` に指定する。
   継承した `Actions` の距離はDAから設定されるので、直接編集しない。対象チームは両チームが既定。

`TBLightSwitch` は `ATBItemBase` を継承する。距離・遮蔽・チーム・操作可否の検証は共通ベースに任せる。
おもちゃを運搬中の人間は収納操作を優先する。それ以外はmainの共通対象選択に従い、
`DA_TBRules` で指定する照準範囲内（既定45度）で最も照準に近いアイテム／捕獲対象を選ぶ。同じ角度なら近い対象を優先する。
E長押しでは繰り返し切り替えない。部屋未設定のスイッチは操作対象にならない。
状態の変更は既存のCharacterのServer RPCから行う。部屋の状態は常時関連Actorとして複製され、
途中参加者も現在の点灯状態を受け取る。再戦時は部屋ごとの初期状態へ戻る。

範囲を重ねないことを推奨する。重なった場合は点灯している部屋が優先する。
これは意図しない暗所保護が隣室に漏れるのを防ぐため。保護距離は全室共通のルール。

DAは試合中は読み取り専用。照明の現在状態は従来どおりサーバーのActorに持ち、DAへは書き込まない。
スイッチのDAは構築時と初期化時に読み込み、参照を保持する。未設定・読み込み失敗時はC++の既定値を使う。
DAの数値を変更したらPlayを開始し直して確認する。`/Game/Data` は既存のCook対象。

## 実際の暗さ

ポストプロセスで画面を暗転させず、登録したライトそのものを消す。
プロジェクトは既にLumen有効・Static Lighting無効。Movableライトは動的な直接光と間接光に対応する。
参考: https://dev.epicgames.com/documentation/unreal-engine/movable-light-mobility-in-unreal-engine

窓からの太陽光、SkyLight、隣室からの光、発光マテリアルは残る。消灯を完全な暗闇にする処理ではない。
実際の暗さは室内で確認し、壁の遮光・ライトの到達範囲・既存RoomExposureを調整する。
保護判定は画素の明るさではなく照明状態に従うので、窓際でも消灯中なら同じ効果になる。
Staticライトの焼き込み光は実行中に消せない。全体のSkyLightを部屋用として登録すると他の部屋にも影響する。

## 検証

- `Tests/RuleTests.cpp`: 点灯時・N未満・Nちょうど・N超過・0m。
- `ToonStory.Lighting.RoomRules`: ライトVisibility、暗い部屋を外から見た距離判定、範囲外、
  重複範囲、回転・スケール、再戦時の初期状態復元。
- `ToonStory.Items.LightSwitch`: 共通の対象選択、部屋未設定の拒否、両チームの切り替え、
  無効化・凍結・範囲外・未知のアクションで状態が変わらないこと、DAによる操作距離の変更。
- `ToonStory.Data.Lighting`: 既定値・共有スイッチDAの存在。
- `ToonStory.Lighting.AuthoredStage`: 上記各マップをStandaloneで起動して実行。
  保存した参照、ライトのMobility、重複割り当て、スイッチ数、人間・おもちゃの体格で
  壁や家具と重ならない床上の操作位置、共通対象選択、操作による消灯・再点灯を確認する。
  スイッチ付近の到達性を検証するもので、開始地点からの経路全体は検証しない。
- 手動: 複数人からの同時視認、両チームのE操作、壁越し操作の拒否、途中参加・LAN同期、実描画の暗さ。
