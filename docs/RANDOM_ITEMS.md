# アイテムのランダム配置

試合開始が成立した時点（隠れる準備時間の開始時）に、サーバーが候補地点とアイテムを抽選します。
生成したActorを全員へ複製するため、各プレイヤーで位置や種類が変わることはありません。
途中の補充はありません。ロビーに戻ると生成分を削除し、次の試合で再抽選します。マップに直接置いたアイテムは削除しません。

## すぐ試す

`TB_StylizedHouse` または `TB_ToyWorldDemoExpanded` で通常どおり試合を開始します。
初期設定は1試合3個です。候補地点はOutlinerの `Gameplay/RandomItems` フォルダにあります。
マーカー自体はゲーム中には表示されません。

- House：床置きのラジオ。部屋内の8地点が候補です。
- Demo：寝室内の床置き候補5地点。リビングは家具・小物が密集しているため、現在のモデル寸法と余白の条件では候補を設けていません。
- 壁付け前提の照明スイッチはDAでランダム配置をオフにしています。既存の固定スイッチはそのまま使えます。

勝利条件に関わる電池やダミーおもちゃは対象外です。既存の固定配置も残しています。
現在のmainにある `TBItemBase` 派生アイテムを使っており、新しい派生アイテムは候補へ追加できます。

## 数値・アイテムを変える

Content Browserで `Content/Data/DA_TBRules` を開き、「ランダム配置」を展開します。

| 項目 | 内容 |
| --- | --- |
| ランダム配置を有効化 | オフにすると生成しません |
| 試合ごとの出現数 | 生成数の上限。初期値3 |
| アイテムの外形間の最短距離 | 今回生成するモデルの外接ボックス間の距離。初期値120cm |
| 障害物との余白 | モデルの左右・前後・上に確保する空間。初期値30cm |
| 設置面の許容高低差 | モデルの設置面で許容する床の高低差。初期値2cm |
| 底面と床の隙間 | モデル底面と床の微小な隙間。初期値0.5cm |
| 床を確認する距離 | 地点の下に床があるか確認する距離。初期値40cm |
| アイテム別設定 | クラスごとのON/OFF・選ばれやすさ・配置種別ごとの変換を一括管理 |

「アイテム別設定」の＋で `TBItemBase` 派生クラスまたはそのBPを**1クラスにつき1件**登録します。

| アイテム別設定の項目 | 内容 |
| --- | --- |
| アイテムクラス | 対象のC++クラス／BPクラス |
| ランダム配置する | オフにすると、そのクラスを全配置種別の抽選から除外 |
| 選ばれやすさ | クラス単位の抽選の重み |
| モデル底面を床に合わせる | 初期値オン。原点や拡大率に関係なく、モデル底面を床へ合わせる |
| 配置種別ごとの変換 | キーに `Floor` / `Wall` 等、値に地点からの位置・向き・大きさを指定 |

例えば `TBNoiseRadio` の「ランダム配置する」をオフにするだけで、床用・壁用の両方を止められます。
重みや変換は残るため、オンに戻せば元の設定で再び抽選されます。変更は次の試合開始時の抽選に反映され、現在配置済みのActorや手置きのアイテムには影響しません。
新規エントリの初期値はオンですが、同梱のDAではラジオのみオン、スイッチはオフです。全体の有効化がオフなら、個別設定にかかわらず生成しません。
BP派生クラスは別クラスとして登録します。親クラスのON/OFFが別の登録済みBPへ自動継承されることはありません。
同じクラスを重複登録するとデータ検証エラーになり、実行時もそのクラスを除外します。

「選ばれやすさ」はその地点に配置できる候補間の重みです。1と2なら後者が2倍選ばれやすくなり、0なら抽選対象外です。
配置種別を増やしてもクラスの重みは増えません。地点の種別と完全一致する変換を優先し、なければ `None` の変換を使います。どちらもなければその地点には出現しません。
同じ種類が複数出現することがあります。最低1個ずつ出す保証はありません。
アイテム固有の効果や音などは、引き続き `DA_NoiseRadio` など各アイテムのDAで調整します。

## 候補地点を追加する

1. 対象のマップを開き、Place Actorsから **TBItemSpawnPoint** を配置します。
2. 原点を床の少し上に置きます。既存の地点は床面から約3cm上です。壁際・家具際・出入口・主要な通路・プレイヤーの開始地点を避け、モデルの大きさに加えて周囲の余白も確保します。
3. Detailsの「ランダム配置」で「この候補を使用」をオンにします。
4. 「配置種別」を設定します。初期設定では床置きが `Floor`、壁付近が `Wall` です。DA側の「配置種別ごとの変換」のキーと同じ名前にしてください。DA側の `None` は完全一致の設定がない種別を対象にします。
5. 地点の向きを、出現したモデルを向けたい方向へ合わせます。モデルの回転・拡大率を適用した後の外形で判定します。
6. 現在の候補はすべて `Floor` です。照明スイッチのような壁付けの配置物は固定配置にしてください。`Wall` は単なる分類名であり、壁の検出・取り付け機能ではありません。
7. マップを保存し、試合を開始して実際の配置を確認します。

DAの「配置種別ごとの変換」は、地点の向き・拡大率を基準とするローカル変換です。
ラジオは `Floor` のみ、オフセットなし、配置用倍率0.5です（仮モデル本体の幅80cmを40cmに調整）。「モデル底面を床に合わせる」がオンなら、最終的な高さはモデル底面から自動計算します。
この設定をオフにすると指定した高さを維持しますが、障害物との余白は引き続き必要です。新しいモデルを登録したら、実画面で向き・余白・操作のしやすさも確認してください。

候補地点またはオフセット先の下に床がない場合や、モデル外形と余白を含む領域に障害物がある場合は、その候補をスキップします。
安全な候補が足りなければ設定数より少なくなります。出現数より多めに地点を用意してください。
オフセット先の床確認は地点の高さを基準に行い、地点より下へ動かした場合は移動先の高さを使います。壁付け用の上方向オフセットは許容します。
モデル外形はStaticMesh／SkinnedMeshから取得し、文字ラベル・インタラクト範囲は含めません。床置きでは外形の中心・四隅・辺の中央（9箇所）の床を確認し、支持が欠ける場合や高低差が大きい場合は置きません。モデル底面を最も高い支持面へ合わせます。
障害物はWorldDynamicまたはVisibilityをブロックする当たり判定で調べます。当たり判定のない装飾や、床の確認点の間にある小さな穴までは保証できません。候補地点は実画面でも確認し、出入口・主要な通路を塞がない場所にしてください。

## 実装と検証

- `UTBItemSpawnDirector`：GameModeに属するサーバー側の抽選・生成・片付け処理。毎フレームの探索は行いません。
- `ATBItemSpawnPoint`：マップに保存する候補地点。
- `ATBLightSwitch::Room`：動的に生成したスイッチでもクライアントが操作対象を参照できるように複製。
- 自動テスト：`ToonStory.Items.RandomSpawns`、`ToonStory.Items.AuthoredRandomSpawns`、`ToonStory.Match.Rematch`。
  `AuthoredRandomSpawns` と `Rematch` はHouseまたはDemoの単体ゲームで実行します。

コードだけでなく、ContentサブモジュールのDAと2つのマップも必要です。
共有時はContent側を先にコミット・pushし、本体でそのContentコミットを記録してから本体を共有してください。
