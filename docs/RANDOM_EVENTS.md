# ランダムイベント

`feat/random-events` はイベントの抽選・実行の基盤と、自動消灯イベントを含む。
mainの照明機能を取り込み済み。共有の `DA_TBRules` に `TBBlackoutEvent` を登録してあるので、
照明設定済みの3ステージは追加配置なしで自動消灯が発生する。

## 調整

`Content/Data/DA_TBRules` を開き、「イベント」を編集する。
既存のルールDAに追加した項目なので、新しいDAの作成や参照の差し替えは不要。

| 項目 | 初期値 | 意味 |
| --- | --- | --- |
| イベントを有効化 | true | 抽選・明示的なイベント実行の両方を許可 |
| 毎秒の発生確率 | 0.01 | 毎秒1%でイベント発生の抽選に当選。0で自然発生なし、1で毎回当選 |
| 発生後の共通クールダウン | 30秒 | 成功後、種類を問わず次のイベントを禁止する時間 |
| イベント候補 | TBBlackoutEvent | `TBRandomEvent` を継承したクラス一覧（共有DAに登録済み） |

値は仮の初期値。DAは試合中に書き換えない。候補一覧は試合ごとに読み込むため、変更後はPlayを開始し直す。
候補数を増やしても総発生確率は増えない。実行条件を満たす候補から等確率で1つ選ぶ。重複登録・未設定・抽象クラスは無視する。
独自のルールDAやC++フォールバックの候補は空。自動消灯を使う場合は同じクラスを登録する。

## 実行の流れ

GameModeにある `TBEventDirector` が、サーバーの試合中（Playing）のみ毎秒抽選する。
初回抽選は試合開始から1秒後。ロビー・リザルト・中断中は実行せず、次の試合では経過時間・CD・イベントインスタンスをリセットする。
勝敗確定のフレームでは抽選しない。処理落ち後に過去の抽選をまとめて実行することもない。

当選 → 実行可能な候補を収集 → 1つ選ぶ → 実行直前に条件を再確認 → 実行成功なら共通CD開始。
候補なし・実行失敗ではCDを消費せず、その回は終了する。
`TryTrigger(EventClass)` で明示的に実行する場合も、登録・試合状態・有効化・実行条件・共通CDの検証を通す。
この経路は発生確率だけを省略する。他のイベント発生元もここを経由させればCDを共有できる。
クライアントからの実行や、イベント内から別イベントを再帰的に発生させることはできない。

## イベントの追加

1. C++またはBlueprintで `TBRandomEvent` を継承する。
2. `CanExecute(World)` を実装し、実行可能な対象がある場合だけtrueを返す。副作用を持たせない（選択前と実行直前に呼ぶ）。
3. `Execute(World)` を実装し、実際に効果を適用した場合だけtrueを返す。
4. Blueprintは `Content/Data` 配下に保存し、`DA_TBRules` のイベント候補へ登録する。
   別フォルダに保存する場合も、パッケージに含まれる参照・Cook設定を維持する。
5. 動作確認では確率を1にすると試しやすい。確認後、調整した確率に戻す。

今回は瞬時に効果を適用するイベント用。イベント自体にTick・時間切れ・復元処理・クライアント向け通知は持たせていない。
継続効果の状態・同期・再戦時の復元は、効果を受けるゲーム側Actorが管理する。
Blueprintからワールドを操作するときは引数のWorldを使用する。

### 自動消灯（実装済み）

`TBBlackoutEvent` が点灯中の部屋から等確率で1室選び、`SetLightsOn(false)` を呼ぶ。
有効なMovableライトが1つ以上登録された部屋のみ対象。空の部屋設定や既に消灯中の部屋は対象にしない。
全室消灯中など、対象がない場合は何も変更せずCDも消費しない。
消灯は自動復旧せず、人間・おもちゃが既存スイッチを使って再点灯できる。再点灯した部屋は再び抽選対象になる。
照明状態の複製・暗所での凍結保護・再戦時の初期状態復元は既存の部屋Actorに任せる。
太陽光・SkyLight・発光素材は既存の照明設定どおり残る。画面全体の暗転や追加の通知演出は行わない。

## 検証

`ToonStory.Events.Scheduling` をStandaloneゲームで実行する。
1秒境界、共通CDと境界、処理落ち、試合外の拒否、実行条件、失敗時のCD非消費、再帰実行の拒否、確率0、無効化、未登録クラス、空の候補を確認する。

`ToonStory.Events.Blackout` は照明設定済みマップのStandaloneゲームで実行する。
共有DAへの登録、1回で1室だけ消灯、実ライトとの一致、共通CD、全室消灯時の失敗、
再点灯後の再発生、空の部屋の除外、試合外の拒否を確認する。
既存の `ToonStory.Items.LightSwitch` と `ToonStory.Lighting.AuthoredStage` で両チームのスイッチ操作も確認する。
