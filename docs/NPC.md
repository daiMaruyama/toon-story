# NPC試作

ロビーの「設定を開く」で「にんげんNPC」「おもちゃNPC」を増減する。
Demo ＋ こども部屋／Kids' Rooms／ArchViz Apartment（検証用Arenaも可）で設定できる。
Demoは電池7/10個と箱の正面への経路を確認。視界制限前にはおもちゃNPC1体で通常必要数5個を回収する動作を確認。視界制限後は通常の開始位置・人間NPC2＋プレイヤー人間1対おもちゃNPC5で、2体の収納と電池1個以上の回収を自動テストで確認。残り3個は家具内などで歩行到達できず、NPCだけで10個回収することは保証しない。
各項目は0で不参加。接続プレイヤーとNPCを合計して最大8人。
右側の「にんげん／おもちゃ」は接続プレイヤーの割り当て人数。
「にんげん」「おもちゃ」の明示的な選択は保持し、「どちらでも」の参加者だけで不足する陣営を埋める。
一人で「どちらでも」を選び、人間NPCだけを追加した場合はおもちゃ側、おもちゃNPCだけなら人間側になる。
NPCを含めて片方の陣営が0人の場合は開始できない。設定を閉じた画面にも開始ボタンと準備状況を表示する。
NPC数を変更できるのはホストだけ。接続プレイヤーが準備OKにすると通常通り開始できる。

- 両陣営の探索は正面90度・14m以内と遮蔽物で制限する。背後や壁の向こうの対象は発見しない。
- 人間NPCは見えている本物・ダミーを同じ条件で選び（距離優先、手前に操作可能なおもちゃがある場合はそちらを優先）、追跡、捕獲、箱の正面への運搬、収納を行う。
  見失った場所は3秒間だけ覚え、その後は巡回へ戻る。
  人間NPCの移動速度は通常の50%（既定で歩行135cm/s・運搬90cm/s）。捕獲後は箱の正面まで運び、通常の長押し処理で収納する。
  新しい対象の発見には1秒かかり、30%の確率で4〜7秒見過ごす。本物・ダミーは同じ条件。気づく前や見過ごし中の視線では凍結させない。
  OverlookChance、RecognitionSeconds、HumanSpeedScaleで調整でき、操作プレイヤーやおもちゃNPCの速度には影響しない。
- おもちゃNPCは見える電池を発見し、家具を回り込む間は最後に見てから12秒間覚えて追う。未発見の電池の位置は使わない。電池が見えなければ直近8か所の巡回地点を避けて探索する。
  自分から見えている人間だけを警戒し、電池への経路上でその人間の視線を確認する。
  消灯した部屋では既存の暗所保護距離を考慮するため、停電イベントも同じ照明状態を通じて反映される。
  危険な経路では物陰へ移動または待機し、安全になれば電池を目指す。
  見られた場合の凍結、電池の接触時間、捕獲・収納はプレイヤーと同じ処理を通る。
- 判断はサーバーだけで行い、キャラクターとPlayerStateを通常通り複製する。
- NPCはステージ到着後に生成する。ロビーの準備人数・移動完了待ちにNPCを含めない。
  結果からロビーへ戻る際にNPC本体とコントローラーを破棄し、人数設定は次の試合にも残す。

既存マップを保存し直さず、NPCありの試合でのみプレイ範囲のNavMeshBoundsを実行時に追加する。
UE5.8のNavMeshResolutionParamsで解像度を指定する。旧CellSize/CellHeight設定だけでは反映されない。
Config/DefaultEngine.iniの動的RecastNavMesh設定と、人間・おもちゃの体格別SupportedAgentsを使用する。
おもちゃNPCは35cm、人間NPCは60cmまでの低い段差・家具を経路に含める。歩行が0.6秒進まない場合は通常のジャンプで越える（ジャンプ間隔は最低1.5秒）。キャラクター本来の衝突・ジャンプ力は変更しない。
運搬中は箱の正面9か所から到達できる位置を探す。経路の再計算は1.5秒間隔に抑え、収納範囲に入ると停止して通常の長押し収納を完了させる。
大きな隙間を越すジャンプ経路や仲間の救助、
難易度設定は今回の試作には含めない。人間NPCは本物とダミーを見分けない。

## 検証

Editor Developmentでビルドする。

- 旧Demoで ToonStory.NPC.FieldTransport：通常の開始位置、人間NPC2＋プレイヤー人間1対おもちゃNPC5で、2体の収納と電池回収。箱の近くへのテスト用移動は行わない。
- Arenaで ToonStory.NPC.Sight：正面の電池・ダミーの発見、背後・遮蔽物・距離による検出拒否。
- Arenaで ToonStory.NPC.DummyCapture：本物も見える状況で近いダミーを選び、捕獲・収納。
- Arenaを新規起動して ToonStory.NPC.MatchLifecycle：
  人数設定の検証、NPC生成、電池取得、捕獲・箱まで移動・収納、ロビー復帰と後片付け。
- 各ゲームステージで ToonStory.NPC.StageNavigation：
  開始位置から電池と箱の正面までの歩行経路。
- 描画を有効にしてTB_Lobbyで ToonStory.NPC.SettingsUI：
  設定ボタンの動作と Saved/Screenshots/NPCSettings.png の画面確認。

NPC MatchLifecycleは単独の新規ArenaまたはDemoで実行する。Demoでは通常必要数5個の収集と収納を確認するため、最大150秒待つ。実際のネットワーク対戦での複数クライアント確認は別途行う。

検証済み：
- Kids' Rooms：電池7/7と箱の正面への経路。
- ArchViz Apartment：電池8/8と箱の正面への経路。
- Arena：両陣営NPCの電池収集・捕獲収納・ロビー復帰。
- TB_Lobbyで ToonStory.NPC.LobbyTravel：NPC設定→Demoへの移動→NPC生成→ロビー復帰。
- ToonStory.Lobby.Counts、ToonStory.Match.StorageHold、Kids' RoomsでのToonStory.Match.Rematch。
- 設定画面のNPC増減ボタンとスクリーンショット。

旧Demoの開始制限は解除済み。マップ・家具・電池の配置は変更していない。
複数PCでのネットワーク対戦と、長時間の行動・難易度の調整は未検証。

## NPC負荷の確認

電池への同期経路探索は1判断あたり最大3件、隠れ場所の候補は最大4件。安全な目標は到着まで維持し、経路の安全性を1.5〜2秒間隔で再確認して、判断時刻をNPCごとに分散する。巡回・隠れ場所は各キャラクターの体格に対応するNavDataを使う。6秒進展がない電池は15秒避けて別の候補へ向かう。
Unreal InsightsのTBNPC_Think、またはCSV profilerのTBNPC/Thinkで判断処理のCPU時間を測定できる。描画負荷や初回NavMesh生成時間は別途計測する。

視界制限を追加する前の計測（旧Demo、単独起動、1280×720、60fps上限、同一カメラ、各15秒）：NPCなし／7体（人間2・おもちゃ5）とも約60fps。ゲームスレッド平均2.07ms／5.01ms、GPU平均12.11ms／12.64ms、NPC判断は7体合計で1フレーム平均0.026ms。初回ロード、エディタ併用、複数PIE、高解像度の負荷はこの比較に含めない。計測中の試合継続もテストで確認した。
